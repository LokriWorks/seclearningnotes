### 摘要与内容导览

本实验用Python编写TCP Reno教学模拟器，观察拥塞窗口cwnd和慢开始阈值ssthresh在不同条件下的变化。程序按RTT推进，支持正常传输、重复ACK和超时三类操作，并将窗口曲线与每一步记录显示在同一界面。

测试先检查无丢包时的窗口增长，再分别触发快重传和超时。初始阈值为64 MSS时，[仿真时刻已删除]窗口达到64；窗口增长到68后，第三个重复ACK使课程模式的窗口降至34，超时则使窗口回到1。程序还设置了不同概率的随机故障，用于比较重传次数和估算吞吐量的变化。

关键词：TCP Reno；拥塞窗口；慢开始；快重传；快恢复

## 一 需求与原理

### 1.1 课程任务

本实验选择题目9“网络拥塞控制机制模拟器（基于TCP Reno）”。设计目标是把慢开始、拥塞避免、快重传和快恢复的变化过程直接显示出来，尤其比较第三个重复ACK与超时对窗口的不同影响。为便于逐步观察，实验采用按RTT更新的状态机模型。

### 1.2 指导书要求与实现对应

| 要求或参考步骤 | 程序中的实现 | 验证位置 |
| --- | --- | --- |
| 初始化参数与阶段标志 | cwnd=1、ssthresh=64、RTT=0、重复ACK=0 | 初始化测试 |
| 慢开始与拥塞避免 | 每RTT翻倍至阈值，之后每RTT加1 | 无丢包预设 |
| 快重传与快恢复 | 第三个重复ACK重传；额外重复ACK加1；新ACK退出 | 逐次ACK按钮与测试 |
| 超时与随机丢包 | 超时重置窗口；可设置事件概率与种子 | 超时按钮、随机场景 |
| 可视化窗口和阈值 | 双曲线、状态栏、事件日志 | 本地界面运行（公开版不附原截图） |
| 无、轻、重丢包对比 | 三类预设与50种子随机实验 | 3.5节与3.7节 |

### 1.3 验收标准

各状态分支应与选定规则一致；前两个重复ACK不触发快重传，第三个只触发一次；额外重复ACK不能重复减半；恢复新ACK和超时均需清空重复ACK计数。界面状态、曲线点和导出记录必须来自同一模型。

### 1.4 协议原理与模型约束

#### 1.4.1 窗口与阈值

cwnd以MSS为单位表示拥塞窗口。ssthresh控制慢开始与拥塞避免的切换。为突出阶段变化，本模型假定发送方有足量数据、接收窗口不限制发送，并以当前cwnd近似满窗口在途量。

指导书原理段将慢开始写为“每收到一个ACK，cwnd翻倍”，参考过程则写为“每RTT翻倍”。本设计采用后者：一个无丢失RTT近似使窗口翻倍，达到阈值后转为每RTT增加1 MSS。真实协议的逐ACK更新不能解释为每个ACK都使整个窗口翻倍。

#### 1.4.2 本设计的规则

| 事件 | 课程简化模式 | 标准Reno对照 |
| --- | --- | --- |
| 无故障RTT | 慢开始翻倍至阈值；拥塞避免加1 | 相同RTT近似 |
| 第三个重复ACK | 阈值=max(旧窗口整除2,2)；窗口=阈值 | 阈值相同；窗口=阈值+3 |
| 额外重复ACK | 窗口增加1 MSS | 相同 |
| 恢复阶段新ACK | 窗口回到阈值并进入拥塞避免 | 相同 |
| 超时 | 阈值减半且最低2；窗口=1，重新慢开始 | 相同状态机近似 |

#### 1.4.3 简化边界

标准对照用于展示RFC 5681中快恢复进入时的+3 MSS规则[1]，并非完整TCP协议栈。本设计不实现字节序号、socket、真实ACK报文、延迟ACK、SACK、有限发送、接收窗口或自适应RTO。超时等待统一折算为2 RTT；阈值最低2 MSS用于边界保护。

### 2.2 状态转移过程

表中Reno、App和Record分别是源码中的类，preset和random_run是函数。运行时的状态存入Record，导出的CSV和JSON保存在“测试记录”目录。

初始化 → 慢开始 → 窗口达到阈值 → 拥塞避免。任一增长阶段收到第三个重复ACK → 快重传事件 → 快恢复。快恢复收到额外重复ACK → 窗口加1并保持快恢复；收到推进累计确认的新ACK → 窗口回到阈值 → 拥塞避免。发生超时 → 窗口回到1 → 慢开始。

快重传是“第三个重复ACK触发重传”的瞬时动作，快恢复是动作后的持续状态。程序以SS、CA和FR保存三个持续状态，通过日志单独标注快重传事件，避免将快重传误当作占据整个RTT的独立阶段。

### 2.3 数据结构

每条Record记录保存事件步、RTT、事件名、窗口、阈值、阶段、重复ACK数和累计重传数。模型更新后向history追加记录。状态栏显示最后一条记录，曲线和CSV使用整段记录，便于把图上的变化与具体事件对应起来。

### 2.4 关键机制设计

#### 2.4.1 初始化与正常推进

Reno构造时校验阈值为不小于2的整数，设置cwnd=1、ssthresh=64、RTT=0、重复ACK计数=0、重传数=0。normal_rtt每次使RTT计数加1；慢开始执行min(2×cwnd, ssthresh)，达到阈值后立即标记拥塞避免。若阈值不是2的幂，也不会直接越过指定阈值。

#### 2.4.2 快重传与快恢复

duplicate_ack每调用一次，重复ACK计数加1。前两次只记录事件；第三次设置阈值、执行一次重传计数并进入快恢复。之后的重复ACK只增加窗口，不再次设置阈值。快恢复后的normal_rtt表示收到推进累计确认的新ACK，将窗口收回阈值，转入拥塞避免并清零重复ACK计数。

#### 2.4.3 超时与随机场景

timeout将仿真时间推进2 RTT，按旧窗口计算新阈值，再将窗口置为1、阶段改为慢开始、重复ACK计数清零。随机场景每轮按p触发一个丢包事件：窗口至少4 MSS时，以70%条件概率选择快重传路径，否则选择超时路径；未触发故障则正常推进。该策略是可复现的教学场景生成方式，不模拟真实链路中丢包原因与位置。

### 3.7 随机故障对比与性能讨论

#### 3.7.1 实验设置与指标

采用课程简化模式，p分别为0、0.05和0.20，每组50个随机种子（0至49），每次固定200个决策轮。p表示每轮产生丢包事件的概率，不是逐包丢包率。固定轮数下，超时会增加等待RTT，故各次仿真总时间可能不同。

为比较各组结果，设置估算指标G：将各无故障轮开始时的cwnd相加，再除以累计仿真RTT，单位为MSS/RTT。故障轮按0计入。本模型没有实际传输字节，因此G只反映当前规则下的窗口与等待开销，不是网卡实测吞吐量。

| p | G均值 | G标准差 | 平均重传 | 平均超时 |
| --- | --- | --- | --- | --- |
| 0.00 | 156.000 | 0.000 | 0.00 | 0.00 |
| 0.05 | 30.319 | 14.952 | 10.82 | 3.68 |
| 0.20 | 5.090 | 1.900 | 41.48 | 22.36 |

#### 3.7.2 结果解释

在当前参数和故障生成规则下，事件概率从0提高到0.20时，平均重传由0升至41.48，平均超时由0升至22.36，估算指标G明显下降。概率0.05组标准差较大，表明有限时长内故障出现的位置也影响窗口增长，不能只展示单个有利种子。

无故障组未设置带宽瓶颈，窗口可持续增加，因此其数值不能用于估计现实网络带宽。若需要真实吞吐实验，应另建可控网络测试环境并显式选择Reno；从任意网站流量或Wireshark窗口字段不能直接证明发送端cwnd或拥塞算法。

#### 3.7.3 结果展示

原窗口轨迹图、随机种子运行记录和结束时刻均已删除。总体规律是故障反馈会使窗口收缩，恢复过程受反馈类型影响。

## 四 总结与附录

### 4.1 问题与处理

实现时需要把“第三个重复ACK”和“恢复期间的额外重复ACK”分开处理。前者更新阈值并触发一次重传，后者只把窗口增加1。如果两种情况使用同一分支，窗口可能被重复减半。程序先判断是否处于快恢复，并通过68→34→35→36→34的测试序列检查这一区别。

### 4.2 局限与改进方向

本模型将数据面和ACK到达抽象为状态事件，适合展示课程机制，但不能验证TCP报文字节级可靠性。可扩展为离散事件数据包网络，维护FlightSize、累计ACK、丢失位置、拥塞队列、接收窗口和自适应RTO，再比较Reno与NewReno在多包丢失下的差异。

界面已提供阈值校验、随机种子、CSV导出和可复现测试。还可增加仿真历史回放、缩放曲线、多个参数方案叠加，以及在固定容量瓶颈下的实际goodput统计。

### 4.3 设计总结

本实验中，同样从68 MSS开始，三个重复ACK使窗口降至34，而超时使窗口回到1。两种反馈后的恢复速度不同，不能把“发生丢包”简单处理成同一种窗口变化。重复ACK还需要累计到三个才触发快重传，前两个不会改变窗口。把这些数值和曲线放在一起，比只列出四个阶段更容易理解Reno的处理过程。

### 4.5 核心源代码

以下为reno_core.py中的正常RTT与重复ACK处理函数。完整可运行程序同时包含GUI、预设、随机实验和测试脚本。

```python
    def normal_rtt(self):
        """一个无丢失RTT，或快恢复后收到推进累计确认的新ACK。"""
        self.rtt += 1
        self.dupacks = 0
        if self.state == FR:
            self.cwnd = self.ssthresh
            self.state = CA
            self.record('新ACK：退出快恢复')
        elif self.cwnd < self.ssthresh:
            self.cwnd = min(2 * self.cwnd, self.ssthresh)
            self.state = CA if self.cwnd >= self.ssthresh else SS
            self.record('正常RTT：慢开始增长')
        else:
            self.cwnd += 1
            self.state = CA
            self.record('正常RTT：拥塞避免增长')
    def duplicate_ack(self):
        """单个重复ACK；同一RTT内的事件保留相同横坐标。"""
        self.dupacks += 1
        if self.state == FR:
            self.cwnd += 1
            self.record('额外重复ACK：窗口加1')
        elif self.dupacks == 3:
            # 满窗口在途假设下，FlightSize用当前cwnd近似。
            self.ssthresh = max(self.cwnd // 2, 2)
            self.cwnd = self.ssthresh + (3 if self.mode == 'standard' else 0)
            self.state = FR
            self.retransmissions += 1
            self.fast_count += 1
            self.record('第3个重复ACK：快重传')
        else:
            self.record(f'第{self.dupacks}个重复ACK：继续等待')
```

#### Reno类中的超时处理

```python
class Reno:
    def timeout(self):
        """将RTO等待抽象为2个RTT，不实现操作系统TCP重传定时器。"""
        self.rtt += 2
        self.ssthresh = max(self.cwnd // 2, 2)
        self.cwnd, self.state, self.dupacks = 1, SS, 0
        self.retransmissions += 1
        self.timeout_count += 1
        self.record('超时：重传并重新慢开始')
```

```python
assert r.cwnd == 68
for _ in range(3): r.duplicate_ack()
assert (r.cwnd, r.ssthresh, r.state) == (34, 34, FR)
r.duplicate_ack()
assert r.cwnd == 35
r.normal_rtt()
assert (r.cwnd, r.state, r.dupacks) == (34, CA, 0)
```
